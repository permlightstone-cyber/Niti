# НИТИ — универсальная цифровая память

## Цель

«Нити» — не социальная сеть публикаций и не набор независимых таблиц. Это управляемая человеком память его жизни, где один факт хранится один раз и может показываться многими способами: на временной линии, в карточке, таблице, журнале профессии или в истории отношений между людьми.

## Выполнено в первой безопасной итерации

Независимая страница **memory.html**. Оригинальная страница index.html и существующий формат localStorage не переписываются. Новая бета предлагает:

- События и планы с известной точностью времени: год, месяц, день, минута или время неизвестно. Нет автоматической подстановки фиктивного времени.
- Версии записей и история исправлений.
- Пользовательские пространства и собственные поля.
- Представления: временная линия по датам, карточки и таблица. Поиск и фильтры по статусу и пространству.
- Связи через пользовательские названия людей, мест или объектов (первый этап, без публичного поиска людей).
- Фото локально в IndexedDB и полная выгрузка в JSON, включая фото. Импорт только добавляет отсутствующие записи и не стирает имеющиеся.
- Перенос данных старой PWA из localStorage **только после явного действия**, с предварительным скачиванием копии прежних данных.
- Никакой отправки личных данных в GitHub или на чужой сервер, никаких скрытых социальных связей и автоматической публикации.

## Ограничения беты (не выдавать за готовую публичную систему)

- IndexedDB хранится на одном устройстве/в одном браузере. Пока нет авторизации, облачной синхронизации, совместного редактирования, фонового резервирования или общей базы с Bahçe и бюджетом.
- Добавлена непрерывная интерактивная шкала с масштабами от десятилетий до минут. Точка начала всей жизни сейчас определяется первой известной датой в данных, а не биографической датой рождения; её настройка ещё требуется.
- Географические часовые пояса хранятся в записи, но на первом этапе ось использует **локальные календарные координаты** без перевода между зонами; для межчасовых перелётов предстоит корректная конверсия.
- Связи сейчас текстовые, не подтверждённые идентичности реальных людей.
- Копию нужно экспортировать вручную. При удалении данных браузера невыгруженные данные могут быть утрачены.
- Перенос из старой PWA работает при наличии данных в localStorage того же origin. Для другого устройства/домена понадобится явный экспорт и конвертер.
- Демо не мигрирует действующую Bahçe автоматически. Прежде чем интегрировать, нужна точная идентификация её реального источника и контракт API.

## Технические сущности

Memory Event:
- id: постоянный идентификатор.
- kind: event|task, status: completed|planned|cancelled.
- title, notes, category, tags[], spaceId.
- start, end в локальном формате с явно указанной точностью precision и IANA zone. Если дата неизвестна, она остаётся пустой.
- links[]: локальные текстовые упоминания на текущем этапе; позже отдельная сущность relation с подтверждением владельцев.
- fields: произвольные типизированные поля рабочего пространства.
- source: система-источник и её ID для будущего дедублицирования.
- revision, history[], createdAt, updatedAt.

Space: id, name, color, fields[{key,label,type}] с типами text, number, date, checkbox.

Asset: id, eventId, blob, mime, filename; копии включают base64.

## Следующие архитектурные этапы

1. Инвентаризация действующих «Нитей», Bahçe и бюджета, экспорт и проверка **восстановления** исходных данных на тестовом профиле.
2. Серверная БД с изолированными пользовательскими хранилищами, шифрованием, аудитом, правами и двусторонней офлайн-синхронизацией. Конфликты — по версиям, не «последняя запись победила» молча.
3. Нормализованный граф: Person, Project, Place, Asset, Event, Relation; подтверждение связей обеими сторонами. Событие, общее для двух людей, связывается с личными представлениями согласно разрешениям.
4. Система раздельных разрешений: только я, выбранные люди, участники события, публично; фотографии, геолокация и семейные/медицинские данные по умолчанию закрыты.
5. Универсальный конструктор представлений: свободные поля, вычисления, диаграммы, масштабы времени (жизнь → год → день → минуты) и профессиональные шаблоны, не создающие независимых копий данных.
6. Библиотека шаблонов с добровольной публикацией структуры: согласие автора, предварительный просмотр, авторство, модерирование и удаление всех частных примеров/данных.
7. Голосовое добавление с предварительным просмотром распознавания и отдельным подтверждением записи.
8. Тест интеграции на реальном дне журнала Bahçe, включая время «приблизительно», переезды, отдельные учётные объекты и отсутствие двойного подсчёта.

## Запуск и тесты

Статическая PWA: откройте memory.html через HTTP(S) на том же origin, что index.html. Не запускать через file://: браузер может ограничить модули и IndexedDB.

Проверка чистых преобразований: node --test tests/memory-core.test.mjs

Ни один файл в этой ветке не содержит приватных записей пользователя или реальных финансовых данных. Действующее приложение не изменено, пока ветка не будет рассмотрена и слита.

## Интерактивная временная шкала

`memory-timeline.mjs` хранит только правила расчёта отображения. У года, месяца и дня есть *диапазон возможного времени*, а не подставленное 12:00; интервалы с приблизительным временем показаны пунктиром. `memory-timeline-ui.mjs` отрисовывает те же события, которые отображают карточки и таблица. Поддержаны два пальца, перетаскивание, колесо мыши, клавиатура, масштабирование и выбор записи нажатием. Это не копии событий в базе.

## Опциональный импорт из Bahçe

Приложение умеет **вручную** принять JSON-снимок, полученный с разрешения владельца. Это не прямая синхронизация: отдельной команды экспорта из действующего приложения пока нет. Пример формата с вымышленными данными:

~~~json
{
  "schema": "niti.bahce.snapshot.v1",
  "objects": [{"objectId": 1, "name": "Объект А"}],
  "workdays": [
    {"date": "2026-11-06", "entries": [
      {"id": "work-001", "objectId": "1", "object": "Объект А", "date": "2026-11-06", "time": "09:00", "endTime": "11:00", "status": "done", "kind": "lawn", "note": "Подстрижена трава", "durationMinutes": 120}
    ], "plans": [{"id": "plan-001", "objectId": "1", "note": "Купить фильтр", "date": "2026-11-07", "status": "planned"}]}
  ],
  "payments": [{"id": "payment-001", "object_id": 1, "date": "2026-11-06", "amount": 100, "currency": "TRY", "note": "Оплата"}]
}
~~~

- Импорт проходит локально, требует явного выбора файла, показывает количество новых записей и подтверждение.
- Ключи исходных записей предотвращают повторное добавление одних и тех же работ, дел и платежей. Изменённые локально записи не перезаписываются.
- Сумма платежа сохраняется в оригинальной валюте, перевод в лиры и признание аванса доходом не производятся.
- Режим синхронизации для последующих изменений на сервере Bahçe ещё не реализован.
